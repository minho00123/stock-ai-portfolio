# 아키텍처와 경계

## 과거 운영 경로

미국 가격 데이터는 Alpaca, 한국은 FinanceDataReader를 사용했다. 거래 API는 각각 Alpaca paper와 KIS 모의투자다. 한국 가격 수집 경로와 주문 경로가 다르므로 두 데이터의 일치가 자동 보장되는 구조는 아니다.

`build_features*.py`는 기술 지표와 시장 ETF 피처를 결합한다. 미래 수익률은 학습 라벨용이며, 모델 입력은 별도 피처 목록으로 선택한다. 미국은 SPY·QQQ를 시장 컨텍스트로 사용한다. 이 과정에서 현재 시점의 종가를 사용하는 것과 해당 종가로 즉시 체결할 수 있는 것은 별개다.

`train_model*.py`는 시간 순서로 나누고 LightGBM을 학습한다. 미국 `feature_selection.py`는 피처 개수를 바꿔 AUC로 모델을 선택한다. 선택·early stopping·평가에 같은 test 구간이 재사용되므로 완전히 분리된 최종 평가가 아니다.

`news_collector.py`는 미국 뉴스와 한국 RSS를 정규화한다. ID는 종목·제목·발행 시각의 SHA-256 앞 16자다. 동일 기사가 다른 제목이나 시간으로 수집되면 별도 뉴스가 될 수 있다. 같은 기사의 종목별 분석 역시 자동으로 통합되지 않는다.

`llm_analyzer.py`는 LEFT JOIN으로 미분석 기사를 찾아 최대 100건을 처리한다. 제목·요약을 API에 전달하고 결과를 `news_analysis`에 저장한다. 캐싱은 같은 뉴스 ID를 재호출하지 않는 방식이며, 프롬프트·모델 변경에 따른 캐시 재평가 정책은 확인되지 않는다. 분석 backlog가 있을 때 실제 신호가 최신 정보를 충분히 반영하는지도 별도 검증하지 않았다.

`llm_signals.py`는 최근 48시간 가중 감성으로 매수 거부·순위 보정을 결정한다. `emergency_exit.py`는 72시간 기준으로 보유 종목을 점검한다. 원본은 ISO 시각 문자열을 SQL에서 직접 비교하고 미래 상한을 두지 않는다. 공개 데모는 UTC datetime 비교로 재작성했으며 원본과 완전히 동일한 실행 구현은 아니다.

`daily_trader*.py`는 DB에서 신호·포지션·행동을 별도로 보관한다. 주문 제출 뒤 `open`을 먼저 기록하므로 `open`이 곧 체결 확인을 뜻하지 않는다. 매도는 `closing` 또는 `emergency_close`로 바뀌고 이후 잔고·체결 정보로 손익을 채운다.

## 외부 API 통합에서 드러난 경계

| 경계 | 확인한 구현 | 제한 |
|---|---|---|
| KIS 인증 | 토큰 만료 10분 전 갱신, 파일 캐시 | 캐시 접근 권한·원자적 교체 검증 없음 |
| KIS 재시도 | 최초 1회 + 최대 3회, 2·5·10초 간격, 기본 15초 timeout | 주문 POST도 재시도하므로 응답 유실 시 중복 가능성. 실제 발생 여부 미확인 |
| 미국 체결 | 최근 주문 ID로 `filled_avg_price` 조회 | 종목·방향별 최근 주문 조회이며 복수 lot 대사는 아님 |
| 한국 청산 | 잔고 부재 + 현재가로 체결가 근사 | 실제 체결 조회 API 미구현, DB PnL에 세금 누락 |
| 시장 시간 | 미국 뉴욕 날짜·거래 캘린더, 한국 KST·수동 휴장 목록 | 동기화가 가드보다 먼저 실행됨. 한국 비상매도는 별도 평일·시간 가드이며 동일 휴장 목록을 사용하지 않음 |
| 관측·알림 | 스크립트 실패 시 오류 알림·후속 리포트 시도 | 개별 실패가 내부에서 처리되면 shell에 0이 반환될 수 있음 |

## 자동화의 실제 범위

`run_morning.sh`는 뉴스 → LLM → 양 시장 비상 점검 → 미국 매매 → 미국 리포트다. `run_kr_trading.sh`는 별도 한국 매매·리포트 사이클이며 `run_intraday.sh`는 뉴스 → LLM → 비상 점검이다. 일정은 스크립트 주석의 권장 시각이며 이번에 원격 cron을 확인하지 않았다.

각 shell 스크립트는 서로 다른 lock 파일을 사용한다. 동일 사이클 중복 실행은 막지만 다른 사이클의 동시 비상매도나 동일 DB 접근까지 직렬화하지 않는다. 정확한 중복 주문 방지·실시간 이벤트 처리·중단 명령(`/halt`)·DART 연동·다중 모델 앙상블은 구현된 기능으로 제시하지 않는다.

## 이번 공개 초안의 경계

실행 코드는 `stock_ai_portfolio/`의 표준 라이브러리 모듈뿐이다. 합성 JSON에서 이미 만들어진 예측·뉴스 점수를 읽으며, 자격증명을 읽거나 SDK를 초기화하는 경로가 없다. 과거 API·ML·shell 코드는 `reference/`의 Markdown 코드 블록에만 보존했다. 실행 파일과 정적 발췌를 구분해 주문 기능이 패키지 import나 데모 실행으로 작동할 가능성을 제거했다.
