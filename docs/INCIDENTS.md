# 장애와 판단 기록

## 주문 상태와 DB 기록의 불일치

원본 미국 트레이더는 주문을 제출하면 DB에 `open`을 기록한다. 동기화는 잔고에 없고 진입일이 오늘보다 과거인 `open`을 `cancelled`로 바꾼다. 주문 상태를 직접 조회해서 취소를 확정하는 조건이 아니다.

예를 들어 금요일 장외에 주문을 제출하고 토요일 잔고가 비어 있으면 위 조건이 참이다. 이후 주문이 체결되더라도 DB가 이미 `cancelled`라면 `status='open'`만 조회하는 만기 청산에서 빠질 수 있다. 최종 검토 문서는 이를 실제 고아 포지션 발생 원인으로 기록했다. 로컬 DB에서도 미국 cancelled 7건 중 5건의 진입일이 금요일이라는 패턴은 확인했다. 다만 당시 개별 브로커 이벤트를 새로 조회해 원인별로 모두 재확정하지는 않았다.

최종 문서는 “미국 거래일 체크 없음”을 지적하지만 현재 코드는 뉴욕 날짜로 거래일을 확인한다. 중요한 것은 **동기화가 그 확인보다 먼저 실행된다**는 점이다. 거래일 가드가 생겼다는 이유로 대기 주문 취소 문제까지 해결됐다고 볼 수 없다. 한국 동기화에도 같은 날짜 조건이 존재한다.

이번 데모는 원본 취소 조건을 순수 함수로 재현한다. 별도의 읽기 전용 탐지 예제는 다음을 구분한다.

- 잔고에 있지만 활성 DB 레코드가 없는 종목
- 활성 DB 레코드 없이 접수·진행 중인 주문
- DB는 open, 잔고는 없지만 진행 중 주문이 있는 상태
- DB는 open이나 잔고·진행 주문 어느 쪽에서도 확인되지 않는 상태

이 탐지는 **새 개선 제안**이며 원본 서버에 적용하지 않았다. 종목 단위 스냅샷 비교이므로 수량·부분체결·lot·취소 경합·다중 주문을 완전히 대사하는 기능은 아니다. 주문의 수명 주기를 확인하지 않고 상태를 자동 변경하는 동작을 추가하지 않았다.

운영 재개를 전제로 한다면 외부 주문 상태·체결 이벤트와 내부 상태를 연결하는 고유키, 명시적 pending 상태, 거래일 캘린더, 정기 대사가 필요하다는 가설을 남길 수 있다. 실제 운영 수정·개선 효과 측정은 이번 범위에 없다.

## LLM 비상매도

최종 검토는 비상매도가 손실의 주원인이라고 강하게 표현한다. 이번 재집계에서도 그 집단의 손익은 부정적이다. 그러나 악재가 있는 종목을 선택해서 파는 규칙이므로 단순 만기 집단과 평균을 비교해 원인을 확정할 수 없다. 매도하지 않았다면 더 하락했는지·반등했는지 검증하지 않았다.

따라서 포트폴리오의 결론은 “도움이 된다는 증거를 얻지 못했고, 관측 결과는 부정적이었다”다. 임계값 완화·강화나 다른 LLM으로 교체하면 좋아진다는 주장도 하지 않는다. 비교 가능한 진입 집단과 동일 기간의 LLM 유무 대조가 다음 검증 설계의 후보이며 미구현이다.

## 손익 정확성과 비용

한국 `reconcile_positions()`는 실제 체결가 대신 현재가를 읽어 청산 손익을 근사한다. 세금도 손익식에 포함되지 않는다. `closed` 3행 가운데 유효 손익이 2개인 점은 이번 분석에서 별도로 표시했다. 브로커 집계와 DB가 다르면 DB의 숫자를 정답으로 가정하지 않는다.

백테스트의 미국 왕복 비용은 0.20%, 한국은 코드에 고정된 세금 0.18%를 포함해 0.31%다. 이는 당시 실험 가정이며 현재 법정 세율이나 실제 계좌 적용 비용을 확인한 값이 아니다.

KIS 재시도는 일시적 실패에 대응하는 구현이지만 주문 POST의 응답만 유실된 경우 중복 제출 위험이 있을 수 있다. 실제 중복 주문 발생 여부는 미확인이다. “재시도 추가로 주문 유실 해결” 같은 개선 성과로 표현하지 않았다.

## 종료 판단

이 프로젝트는 기능 구현과 약 2개월의 모의 운영까지 진행됐지만, 검증 한계와 상태 관리 문제를 발견했다. 최종 검토 기록은 실자금 전환 취소와 자동 실행 중단을 선택했다. 실제 자금 손실을 경험한 사례나 수익 달성 사례로 바꾸지 않고, 추가 비용·불확실성을 감수할 이유가 충분하지 않았던 의사결정으로 설명한다.
